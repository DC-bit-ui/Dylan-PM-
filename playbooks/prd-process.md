# Playbook: PRD Process

> From idea to approved spec. The default path Dylan follows for any build-needs-a-doc piece of work.

## Steps

1. **Frame the problem** with `pm-strategist` — confirm the problem is real, important, and the right shape for a PRD (not a one-pager or a research memo).
2. **Validate the user need** — if you don't already have research in `memory/deliverables/research/`, dispatch `researcher`.
3. **Validate the metric** — confirm the success metric exists and is measurable; dispatch `data-analyst` if numbers are involved.
4. **Draft v1** with `/prd`. Don't agonize — assumptions are fine if marked.
5. **Pressure test** with `critic`. Resolve top concerns before sharing.
6. **Review with stakeholders** — engineering, design, data. Use comments, don't restart the doc.
7. **Decision moment** — capture with `/decision` if any non-obvious calls were made.
8. **Mark approved** — update PRD status, link from initiative file, update INDEX.
9. **Kickoff** — use `playbooks/new-initiative.md` if not already done.
10. **Post-launch** — link the launch retro back to the PRD.

## Quality gates

- TL;DR survives a stranger reading it cold.
- Success metric is in `memory/business/metrics.md`.
- Out-of-scope section is non-empty.
- Critic's top concern has a documented response.
