# Playbook: Weekly Stakeholder Update

## Cadence
- Every Friday morning (or Monday — Dylan's call)
- One update per audience that needs one (don't write one update for all audiences)

## Steps

1. **List audiences** — derive from `memory/people/roster.md` filtered to "needs update".
2. **Refresh state** — dispatch `initiative-tracker` for current statuses.
3. **Refresh numbers** — dispatch `data-analyst` for the 1-3 metrics each audience cares about.
4. **Draft per audience** — `/stakeholder-update` per audience, using the right archetype (exec / cross-functional / team).
5. **Quality pass** — `stakeholder-comms` does a tone pass; `critic` does a "what's missing" pass.
6. **Send.** Save the sent version to `memory/deliverables/updates/`.
7. **Capture responses** — if a stakeholder responds with new context or asks, route to `meeting-synthesizer` and update the relevant memory files.

## Heuristics

- If the update has nothing red and no asks, ask whether it needs to send at all.
- Keep a running "things people asked" log per audience — patterns reveal what they actually care about.
