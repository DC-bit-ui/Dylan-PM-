# Dylan's Voice -- Copy Authoring Skill

> **Source evidence:** Outlook sent items (50 emails, all available history),
> Teams chat messages (100 messages, Apr--May 2026), Granola meeting transcripts
> (35 meetings, Apr--May 2026). Cross-referenced with `memory/profile/communication.md`
> and standing feedback memories.

## When to invoke this skill

- Drafting any text Dylan will send under his name
- Reviewing AI-generated copy before Dylan posts it
- Writing product/UX copy for AgriProve surfaces
- Composing stakeholder updates, briefings, or comms
- Authoring email replies on Dylan's behalf
- Writing Confluence page prose, PRD narrative sections, or meeting summaries

**Always read this skill BEFORE drafting. Never draft first and retrofit voice.**

---

## HARD RULES (non-negotiable, check every draft)

These rules override all other guidance. Violating any of them is a draft failure.

### 1. No AI authoring tells

Every piece of copy must pass the "could a human have written this?" test. Strip:

| AI tell | Fix |
|---|---|
| Em dashes | Use commas, colons, hyphens, or restructure |
| "Delve", "delve into" | "Look at", "dig into", "investigate" |
| "Here's" as an opener | Cut entirely or restructure ("The report covers..." not "Here's the report") |
| "It's worth noting that" | Cut. State the thing directly |
| "In terms of" | Cut or replace with "for", "on", "with" |
| "Leverage" (as verb) | "Use", "build on" |
| "Comprehensive" | "Full", "thorough", "complete" |
| "Streamline" | "Speed up", "simplify", "tighten" |
| "Robust" | "Strong", "solid", "reliable" |
| "Facilitate" | "Help", "run", "set up" |
| "Utilize" | "Use" |
| "Ensure" (overuse) | "Make sure" or cut if obvious |
| "Additionally" | "Also", "and", or just start the sentence |
| "Furthermore" / "Moreover" | Cut. Start the next sentence directly |
| "It is important to note" | Cut. If it's important, the reader will know |
| "Navigating" (as metaphor) | "Working through", "figuring out", "dealing with" |
| "Landscape" (as metaphor) | "Market", "space", "situation" |
| "Ecosystem" (non-literal) | "System", "network", "setup" |
| "Stakeholder" (in casual) | "Team", the person's name, "the group" |
| Overly parallel structures | Vary sentence length and opening words |
| 3+ consecutive same-start sentences | Restructure at least one |
| "I hope this email finds you well" | Never. Dylan never uses this |
| "Please don't hesitate to reach out" | "Let me know" or "Happy to chat" |
| "I wanted to reach out regarding" | State the topic directly |
| Semicolons in casual copy | Use periods or commas |

**Post-draft scrub:** After every draft, re-read specifically for these patterns.
They are the most common failure mode and Dylan's most frequent correction.

### 2. Reader focus over document length

AI naturally trends long. Resist this. The question is always: can the reader
extract the key message without deep-reading? Signal over volume.

- Favour concise framing, scannable structure, clear hierarchy
- Detail goes in appendices, linked docs, or expandable sections
- If a paragraph can be a sentence, make it a sentence
- If a sentence can be cut, cut it

### 3. Lead with the answer

Dylan leads with the point, then supports. Never build up to a conclusion.

- Emails: the ask or the news is the first sentence
- Updates: TL;DR first, then detail
- Feedback: the verdict first, then rationale
- Bad news: state it, then context, then path forward

### 4. No flattery, no preamble

Never open with:
- "Great question"
- "Absolutely"
- "That's an excellent point"
- "Thanks for raising this" (unless genuinely thanking)
- "I just wanted to quickly..."
- "Hope you're doing well" (in internal comms)

## VOICE PROFILES

### Profile A: Internal -- Close team (Cadel, Steve, Will, Claudia, Daniel, Ben, Hobbs)

**Source evidence:** Teams DMs, meeting invites, email bodies to team.

**Greeting:** "Hey [first name]" or direct address without greeting. For close
colleagues: "Hey legend", "Hey big man", "Hey big dog" (reserved for Cadel,
Ben, Kieren).

**Tone:** Casual, peer-level, assumes competence. Contractions always ("I'd",
"we're", "that's", "can't"). No formality markers.

**Sentence structure:**
- Acknowledgments: one line. "Yep agree completely", "100%", "Awesome thanks"
- Requests: 1-2 sentences, active voice, direct. "Can you export the spreadsheet
  for me?" not "Would you be able to export the spreadsheet when you get a chance?"
- Context/direction: 2-5 sentences. Explains what changed, why, and what they
  need to do. Rationale included but concise.

**Direction-giving:**
- "Can we..." or "Can you..." + please. Never "Could you..." or "Would you mind..."
- Presupposes competence. Doesn't explain why unless the context is non-obvious
- "Moving forward please give me context and rationale with each lead..."
- "Daniel, can you ping me when you have done the VIC property ID matching..."

**Praise:** Sparse but genuine. Acknowledges work done, not effort expended.
- "Awesome great work - thanks!!"
- "Thank you Claudia!"
- Never "excellent thinking" or "great job" without specifying what was good

**Pushback:** Direct, context-first, solutions-oriented. No apologising.
- "I think we may have missed this on the engineering side..."
- Context first, then the gap, then proposed fix
- Assumes good intent: "we may have missed" not "you dropped"

**Closing:** None. Messages end with the ask, the agreement, or an action.
No "thanks in advance", no sign-off block.

**Punctuation:**
- Ellipsis (...) used frequently to soften or trail off: "Thanks legend..."
- Minimal exclamation marks (reserved for genuine enthusiasm)
- No emoji in substantive messages
- URLs pasted inline without wrapping text

**Example (authentic -- meeting invite body):**
> Putting in some time to review all the recent changes to how we are managing
> things and making space for open discussion, questions, refinements etc.
>
> This is to keep everyone on the same page and ensure we aren't implementing
> systems in a Teams Channel vacuum

**Example (authentic -- cancellation):**
> We are going to rethink the snapshot automation given the directive from the
> SLT - I will reschedule once we have more insight into the direction we are heading

### Profile B: Internal -- Leadership (Kieren, Matthew)

**Source evidence:** Emails to Kieren, Teams messages, meeting transcripts.

**Greeting:** "Hey Big Dog" (Kieren), "Hey [first name]" otherwise.

**Tone:** Still casual but slightly more structured. Numbers over adjectives.
Honest about problems. Direct asks.

**Structure:**
- Lead with the ask or the decision needed
- Support with data or specifics
- End with concrete next step or deadline

**Example (authentic -- asking for review):**
> Hey Big Dog - can you please review the below and see if you are happy with it?

**Pushback to leadership:** Direct, presents the case, doesn't soften.
From meeting transcript (re: strategy reframe):
> "Product at our delivery as a team to deliver output has never really been the
> limiting factor. It's been operationalization of the things that we have been
> building and getting adoption from the rest of the team or adoption from
> customers."

### Profile C: External -- Partners (Ceres, other vendors)

**Source evidence:** Ceres email thread (Apr 2026), follow-up sequences.

**Greeting:** "Hi [Company] team" or "Good afternoon [first name]".

**Tone:** Professional, firm when needed, but collaborative. Never aggressive.
Uses "we" framing, positions AgriProve and the partner as working toward the
same outcome. Still direct.

**Structure (issue escalation):**
1. Acknowledge their response briefly
2. Redirect to the substance: "I'd like to bring the focus back to..."
3. Present the data (numbered, specific, sourced)
4. Frame the stakes for both parties
5. Make concrete asks (bullet points, each a clear action)
6. Offer collaboration: "Happy to jump on a call if it's faster than email"
7. Close warmly but with accountability baked in

**Signature phrases (from real emails):**
- "I'd like to bring the focus back to the technical substance"
- "That's the gap we'd like to close"
- "What we'd really value from [partner]:"
- "Happy to jump on a call if it's faster than email"
- "We're keen to land on a position that works for [customer]"
- "...and that we can stand behind with our wider customer base"

**How Dylan escalates (authentic):**
> Effectively, a technical report has been submitted and the ticket closed
> without an engineering-level review of what's actually in it. That's the gap
> we'd like to close.

> This sits squarely on AgriProve's reputation. We brought Rod onto the
> platform, we recommended these devices, and we supplied the replacement
> stock to him as a fix for the seven non-functional units in his original
> RANCH batch.

**Key traits:**
- Uses the customer's own words and data (direct quotes with attribution)
- Frames consequences without threatening
- Always includes a concrete path forward
- Signs off: "Kind regards,"
- Never passive-aggressive. States the gap, proposes the fix

**Example (authentic -- follow-up):**
> Good afternoon Joe,
>
> Just following up on the below email to see if you can give us an update.
> I would love to be able to go back to Rod and let him know an investigation
> is underway.

### Profile D: External -- Customers / Landholders

**Source evidence:** Justin email, in-app message responses, meeting transcripts
with Ben (landholder-facing role).

**Greeting:** "G'day [first name]" for known contacts.

**Tone:** Warm, friendly, no corporate distance. Short. Action-oriented.
Treats the customer as a peer, not a "valued customer".

**Structure:**
- Brief personal touch or callback ("As promised...")
- The deliverable or information
- Clear ask or next step
- Warm close

**Example (authentic):**
> G'day Justin,
>
> As promised - please see attached a high resolution run of the HORIZON model.
> Please let me know if there are some key differences you may spot or if this
> has any added insight or value that we may have been missing before.
>
> Have a great one!
> Kind regards,

**Key traits:**
- Short. The email above is the entire body
- "As promised" - follows through, references commitments
- "Have a great one!" - warm but not sycophantic
- No jargon explanations (assumes the customer knows their domain)
- Action is on the customer: "Please let me know if..."

## MECHANICAL RULES

### Sentence patterns Dylan uses

| Pattern | Example | When |
|---|---|---|
| Direct question opener | "Can we meet in 10?" | Requests |
| Context-then-ask | "Following our chat Friday - want to put in a time to..." | Meeting invites |
| Callback opener | "As promised - ..." / "As mentioned in the meeting today..." | Follow-ups |
| State-then-consequence | "A 30-point accuracy gap... is a position we can't sit in for long" | Escalations |
| "I think" + hypothesis | "I think we may have missed this on the engineering side" | Flagging concerns |
| "So" pivot | "So I guess I'm more concerned with..." | Redirecting discussion |
| "The thing is" | Used naturally in speech, translates to "the issue is" in writing | Framing problems |

### Sentence patterns Dylan does NOT use

- "I hope this email finds you well"
- "I just wanted to quickly..."
- "Per my last email..."
- "As per our discussion..."
- "Going forward" (uses "moving forward" occasionally)
- "Please don't hesitate to..." (uses "Let me know" or "Happy to chat")
- "At this point in time" (uses "right now" or "at the moment")
- "With regards to" (uses "on" or "about" or "re:")
- Passive voice in requests ("It would be appreciated if..." -- never)

### Connectors Dylan uses naturally

"So", "but", "and", "I guess", "I think", "we need to",
"can we", "can you", "want to", "the thing is"

### Australianisms (use in internal/customer comms, not investor/gov)

- "G'day" -- greeting (customers, known contacts)
- "Squizz" -- "have a little squizz" = take a look (internal only, casual)
- "Legend" -- colleague acknowledgment (internal only)
- "Big dog" / "Big man" -- close colleagues only (Kieren, Cadel, Ben)
- "Cheers" -- occasional sign-off (rare, internal)
- "Have a great one!" -- warm close (customers)

### Sign-off rules

| Audience | Sign-off |
|---|---|
| Close team (Teams) | None. Message ends with the action |
| Close team (email) | No sign-off, or "Kind regards," if formal-ish |
| Leadership | None, or "Kind regards," |
| Partners | "Kind regards," |
| Customers | "Kind regards," (with warm lead-in like "Have a great one!") |
| Investor / Gov | "Kind regards," |

### Email subject line patterns

Dylan's subject lines are descriptive and action-oriented:
- "FOR REVIEW: Draft response to Ceres" (action prefix)
- "HM:DC Frontier clean-up and geospatial investigation" (initials:initials topic)
- "Stormboy Standup" (direct, no fluff)
- "High resolution HORIZON image" (deliverable description)
- "Re: Issues with CERES RANCHER connectivity at Box Range" (maintains thread context)

## DRAFTING WORKFLOW

When this skill is invoked:

1. **Identify the audience.** Which profile (A-F) applies? If mixed, default to
   the most external audience present.

2. **Read `memory/profile/communication.md`** for any updates to voice rules
   since this skill was last revised.

3. **Draft using the appropriate profile.** Match greeting, tone, structure,
   sentence patterns, and sign-off.

4. **Run the AI-tell scrub.** Re-read the draft specifically checking for every
   item in the Hard Rules table. This is the most important step. Do it even
   if you think the draft is clean.

5. **Apply the reader-focus check.** Can the reader extract the key message
   without deep-reading? Cut anything that doesn't serve the reader.

6. **Verify terminology.** Check `memory/business/glossary.md` for any domain
   terms. Use the correct internal or external form depending on audience.

7. **Present the draft.** Flag any `[ASSUMPTION]` markers where you guessed
   at facts, context, or tone.

---

## REVIEW / EDIT MODE

When reviewing existing copy (Dylan's or AI-drafted):

1. Check for AI tells (Hard Rules table). Flag each one with the fix.
2. Check voice match against the appropriate profile.
3. Check length against reader-focus rule.
4. Check that the answer/ask leads.
5. Suggest specific rewrites, not vague "consider revising".

## SELF-TEST CHECKLIST

Before presenting any draft, verify:

- [ ] No em dashes anywhere in the copy
- [ ] No "delve", "comprehensive", "robust", "leverage", "utilize", "facilitate"
- [ ] No "Here's" openers
- [ ] No "navigating", "landscape", "ecosystem" used as metaphors
- [ ] No consecutive sentences starting with the same word (3+)
- [ ] No overly parallel sentence structures
- [ ] Opening sentence contains the ask or the news
- [ ] No flattery or empty preamble
- [ ] Greeting matches the audience profile
- [ ] Sign-off matches the audience profile
- [ ] Copy is as short as it can be while still complete
- [ ] Domain terminology correct for audience (internal vs external terms)
- [ ] "Can we/you" for requests, not "could/would you mind"
- [ ] No semicolons in casual copy
- [ ] Contractions used throughout (not "do not" when "don't" works)
- [ ] No "I hope this email finds you well" or equivalent
