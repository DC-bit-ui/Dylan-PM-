# 2026-05-14 — ISO terminology applies to STATS only, never operational surfaces

## Rule (durable)

When aligning AgriProve language to the ISO 9001 certified scope (or any audit-grade terminology), apply the alignment **only to leadership-facing analytical surfaces**. Never propagate to operational surfaces where the team is doing the work.

**Specifically for the Conversion Tracker:**
- STATS tab — ISO-aligned (✓ done 2026-05-14)
- WORK / ASK / BRAIN tabs — keep the working language (deals · wins · calls · plays · objection cards)
- Rep-facing queues, exemplar cards, action buttons — keep working language

## Why

Two reasons Dylan called out:

1. **Operational utility.** Reps don't think in audit-grade language. Ben, Hobbs, and Claudia work in "deals" and "wins" — that's the language of HubSpot, of the standup, of the call. Forcing them to translate slows their work without adding value.
2. **Insight overshadow.** Audit-grade language is precise but heavy. When applied to action-shaped surfaces, the formality drowns the operational signal. The system's value is what it tells reps to do; the language has to get out of the way.

The STATS tab is the exception because:
- Audience is leadership (Will, Kieren, Matthew, Stephen) — they read the language Auditors do.
- Surface is read-only (no actions live there) — alignment doesn't cost workflow speed.
- ISO certification framework lives at this level, so terminology coherence here matters.

## How to apply

- **For any future terminology question** ("should we use X term or Y?"), check the surface first. If it's a place where reps take action, use the team's working language. If it's a place where leadership reads stats, use audit-aligned language.
- **For new analytical surfaces**, default to ISO-aligned where the term has a clean mapping. Use the canonical reference at `shared-growth-memory/team-brain/iso-certification/iso-terminology-reference.md`.
- **For new operational surfaces**, default to HubSpot-native + team-spoken language. ISO terms only appear if a rep is explicitly looking at audit-relevant data inside that surface.
